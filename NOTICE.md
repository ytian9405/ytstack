# Sources and adaptations

ytstack is a small personal skill pack. It uses pstack's design of narrowly scoped skills with explicit evidence, reusable project instructions, and readable writing. It does not include the pstack coordinator, model routing, hooks, or runtime mapping system.

The copied or adapted upstream files come from `cursor/plugins/pstack`, copyright 2026 Lauren Tan, under the MIT License retained in `LICENSE`. The frozen source commit is `ae5650febf4320793844c12c4adaa937f417f8da`.

- `bro`: upstream instruction kept as the first line. Adds Chinese triggers and rules that keep conclusions, numbers, and alternatives.
- `technical-bro`: technical-writing instruction body retained. The name, heading, and invocation description are renamed; its `unslop` dependency is read through a package-relative link. Independent use exposed an unsolicited vocabulary-diff requirement, so proposals now require an explicit rule-maintenance request and an actual pattern in the input. A short language rule preserves the requested language, output format, and literal technical identifiers.
- `unslop`: upstream rules unchanged; appends Chinese rules 34-42. Commands, code blocks, file paths, verbatim error text, and quoted words are copied as-is. Bundled so technical-bro has no dependency on an external pstack installation.
- `acceptance-criteria`: new in v0.2. Upstream has no skill that writes criteria before implementation. The falsifiable-predicate idea comes from pstack's `figure-it-out`; no upstream text is copied. The skill directory carries the package license for uniformity.
- `voice/plain-talk.md`: new in v0.2. Its write-it-right-while-drafting approach comes from the "Writing the reply" section of pstack's `poteto-mode`; the rules themselves are new and target Codex's GPT models in Chinese.
- `create-test-skill`: adapted from create-verification-skill. Keeps repository-first investigation, real user paths, generated project skills, a maintained case index, evidence, owned cleanup, and an actual proving run. Adds explicit executable behavior assertions, demonstrated failure detection, incremental updates, distinct test-artifact/product results, and host-independent destinations. The required behavior principles are included directly rather than importing the full principles collection.
- `in-your-own-words`: upstream instruction kept as the first line. Keeps `disable-model-invocation: true` for Claude Code, and Codex metadata sets `allow_implicit_invocation: false`, so it runs only when the user asks. Adds Chinese rules: restate in 3 to 5 sentences as a fallible reading, mark the user's guessed cause as a guess, do not plan or edit, stop for confirmation. The confirmed goal is the full restatement after the user's corrections. Acceptance-criteria openings take one sentence from it. Worker briefs and 交接说明 purpose use the full version.
- `ketchup`: translated and adapted. Keeps the window since the user's last message for catch-up only, the read-only catch-up, the action-item fields, and the rule against cutting items. The catch-up opening stays within about 300 Chinese characters. Decision items stay, about 60 characters each. The 交接说明 file is not under that cap. Spending, deletion, and irreversible calls are listed separately and first. Drops pictures, `/visualize`, and video. Catch-up writes nothing. Writing a 交接说明 updates one file for a later session or another computer. Giving the work to another agent right now is orca-cli, and the note can still be written. Pickup checks claimed completions on the real artifact, reports, then continues only listed next steps. Voice rules are written in the skill. It does not depend on `bro`. Adds a 交接说明 section and a pickup section rewritten from poteto-mode's pause-safely and session-pickup playbooks; no playbook text is copied.
- `teach`: translated and merged. The `how` and `why` skills are folded in as single-agent steps. Their subagents, model routing, and seven external evidence sources are not included. The agent reads the code and git history itself and does not invoke `how` or `why`. `why`'s confidence tiers are reduced to three: a cited source, an inference, and not found. A user's own guess is not confirmed. Diagrams are drawn only when the host has a drawing tool. Otherwise the steps are written in text. Reads bundled `unslop`.

The other skills omit the upstream `disable-model-invocation: true` field and use normal host discovery. `in-your-own-words` keeps that field and runs only when the user names `$in-your-own-words` or `/in-your-own-words`. Bro remains short. Its description sends a previous-reply “I don't understand” to itself, and sends a mixed question about how a mechanism works to `teach`. Its instruction body is unchanged. technical-bro retains technical-writing's scope and four writing layers. Its new name does not turn it into a general simplification command.

`michael-denyer/pstack-claude`, commit `8ecae6893912d2bbb3b841c09a8d76e61a4d708b`, informed the shared source layout and separation of host-specific discovery from skill instructions. No port-specific implementation or session hook is copied. That repository is also MIT-licensed; Michael Denyer is credited here for the design reference.

`provenance.json` records source URLs, commits, original hashes, adopted paths, and intended changes. `tools/validate.py` checks local copied-body hashes. Full host validation and behavioral test results are recorded separately; content hashes do not establish behavior.

Each skill directory also carries the full license so a standalone copied installation retains the copyright and permission notice.
