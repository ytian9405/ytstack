# Ledger Lite 项目测试

适用于修改本项目后的验收，或确认 CLI 的用户行为仍符合 README.md。所有命令从项目根目录执行，只依赖 Python 3.9+ 标准库；不联网、不安装依赖。

## 执行步骤

1. 先阅读 `README.md` 和 `tests/test_smoke.py`、`tests/test_behavior.py`。以 README 产品合同为准，保留已有测试。不得为使测试通过而改动合同。
2. 运行原有发现入口：
   ```sh
   python3 -m unittest discover -s tests -v
   ```
3. 运行包含基线和回归检测的证据脚本：
   ```sh
   python3 scripts/verify_tests.py
   ```
   脚本先运行完整基线，基线成功后，依次在系统临时目录复制 CLI 和测试并引入单项回归。必须得到基线退出码 0，六个回归均 `detected: true`，最终 `passed: true` 且脚本退出码 0。基线失败时不运行变异；不能把跳过当成成功。
4. 阅读 `test-results/baseline.log`、六个 `M*.log` 及 `verification.json`。后者记录时间、Python 版本、执行命令、输入文件 SHA-256 和每个回归结果。每次运行会覆盖这些固定名称的文件；需要保留旧证据时先另存。
5. 如失败，按日志复现到具体用例，报告实际行为与 README 合同的差别。不要仅以非零退出证明检测有效：脚本要求预定用例出现断言失败且没有测试 ERROR。锚点不唯一会拒绝运行对应变异，应检查脚本与当前实现是否仍相符。
6. 最终报告命令、基线测试数、回归检测数、证据路径及未覆盖范围。产品代码或合同如有获授权的变更，应同步复核行为用例与变异锚点，重新生成证据。

## 用例与合同对应

| ID | 用户行为和断言 |
| --- | --- |
| 现有 Smoke | 空账本汇总精确 JSON |
| LL01 | 缺失文件时 list 和 summary 为空，读取不创建文件 |
| LL02 | 首个 ID=1，完整记录、Unicode 和首尾空格、正整数边界、顺序与跨进程持久化、自动创建父目录 |
| LL03 | 作废返回完整记录，保留字段和列表位置、跨进程持久化、重复作废无额外副作用、作废最大 ID 后不复用 |
| LL04 | 多类别及同类别累计，精确类别字符串、仅计未作废、全部作废后空汇总，列表保留全部记录 |
| LL05 | 非正/非整数金额、空/全空白标题及类别均失败，stderr 有错误，原文件字节及列表不变，失败不消耗 ID |
| LL06 | 不存在的 ID 作废失败，stderr 有错误，已有字节与记录不变 |
| LL07 | 缺失账本上的失败写入不会创建状态文件 |

每个测试使用 `TemporaryDirectory` 独立状态路径，通过 `addCleanup` 清理；每次 CLI 调用启动独立进程，超时 10 秒。成功命令校验退出码、单个合法 JSON 值及预期内容，不依赖 JSON 键顺序。失败命令校验非零退出与非空 stderr，不依赖具体错误文案。

## 回归检测

| ID | 临时引入的错误 | 必须失败的用例 |
| --- | --- | --- |
| M01 | 汇总包含作废记录 | LL04 |
| M02 | 添加时裁剪标题空格 | LL02 |
| M03 | ID 只由活动记录计算，复用作废 ID | LL03 |
| M04 | 接受金额零 | LL05 |
| M05 | 作废时删除记录 | LL03 |
| M06 | 同类别金额被覆盖而非累加 | LL04 |

变异只写临时副本，不修改项目 CLI。临时副本退出上下文后自动删除；测试状态也自动清理。`__pycache__` 是 Python 运行时可重建的缓存，证据文件保留在项目内。

## 范围限制

不覆盖 README 明确排除的损坏 JSON、并发写入、文件系统权限异常；不做性能、任意规模账本、所有 Python 版本或操作系统兼容性证明。六种定向回归不是穷尽变异测试。没有假设错误信息的具体文案或状态 JSON 的内部排版格式；重复作废仅检查当前实现已有文件字节不变和公开行为不变。
