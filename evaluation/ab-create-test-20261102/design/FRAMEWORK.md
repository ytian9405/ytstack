# Ledger Lite 测试技能 A/B 评价框架

版本：1.0；冻结日期：2026-11-02。设计依据仅为任务描述与 README 合同，未查看任何技能、实验产物或历史评测。本文与 framework.json 是同一份预注册规则；出现不一致时暂停评分、记录差异，不择优解释。冻结后不得根据组别或结果改权重、变异或门槛。

## 评价对象与分数

对象是一次运行交付的完整项目测试工作流，包括新增测试、保留的旧测试、可复用操作说明和执行证据。共四次运行，先用随机编号盲评，再解盲。结构、文件名、文档长度、报告份数、测试数量不计分；不要求任何技能专有约定。普通 Markdown 操作说明只要具有同等可调用功能，也能得满分。

质量满分 100：行为价值 60、复用性 25、执行可信度 15。各项分值 = 权重 × 等级 / 2，等级只能是 0、1、2。成本独立报告，不混入质量分：模型用量、时间与质量不存在事先约定的兑换比例。只有质量全部可评估且无重大缺陷时，才输出可比较的总分。

四个维度分别回答：测得对不对、别人能否重复使用、所称执行是否真实、用了多少资源。相同根因只在所属条目扣分；其他条目只写交叉影响或 UNKNOWN，不重复处罚。

## A. 行为价值：60 分

对每项行为使用相同锚点：

- 0：没有有效检查，或检查在干净实现上错误失败，或唯一检查不能识别该项已验证的代表性缺陷。
- 1：有正确、可执行的检查，但只覆盖该项部分要求，或该项多个固定变异中只识别部分。
- 2：覆盖该项全部要求，有针对可观察结果的断言，并识别该项全部适用且经验证的固定变异。

不以读取代码、运行命令或打印结果本身作为有效检查。端到端、子进程、测试框架或自定义断言脚本均可。隐藏变异是验证同一行为项的证据，不另设变异分，避免一次遗漏扣两次。

| ID | 可观察指标与边界 | 权重 | 固定变异 |
|---|---|---:|---|
| B01 | add 原样保留标题与类别，包括前后空格和非 ASCII 字符；检查返回或存储的实际值 | 5 | M01 去掉标题空格；M02 去掉类别空格 |
| B02 | 正整数分可接受；0、负数、非整数输入被拒绝，非零状态码、stderr 有错误且原数据不变 | 6 | M03 接受 0；M04 接受负数；M05 接受小数并截断 |
| B03 | 首个 id 为 1，连续新增单调递增；作废后新增不重用 id | 5 | M06 首 id 为 0；M07 按有效记录数生成 id |
| B04 | 一个进程写入后另一个进程读到原数据；后续写入保留此前记录 | 5 | M08 add 不持久化；M09 第二次 add 覆盖旧记录 |
| B05 | list 对空账本和多记录账本返回准确集合，包含已作废记录及其状态；不要求合同未规定的排序 | 5 | M10 list 过滤已作废记录 |
| B06 | void 标记目标记录，保留记录及原字段，不改变其他记录 | 5 | M11 void 物理删除；M12 void 标记全部记录 |
| B07 | 重复 void 同一 id 成功且状态无副作用 | 4 | M13 第二次 void 报错 |
| B08 | summary 的 count、total_cents 与有效记录一致，包括空账本和全部作废；仅统计未作废记录 | 6 | M14 总额包含作废记录；M15 count 包含作废记录 |
| B09 | summary.by_category 按原类别分别计算有效金额，类别间不串账，作废金额不计入 | 4 | M16 全部金额归入第一类别 |
| B10 | 空白标题、空白类别、未知 void id 均拒绝；非零退出、stderr 有错误、已有数据不变 | 6 | M17 接受空白标题；M18 接受空白类别；M19 未知 id 静默成功 |
| B11 | 缺失状态表现为空账本，首次写入创建不存在的多层父目录 | 5 | M20 缺失状态报错；M21 不创建父目录 |
| B12 | add/list/void/summary 成功输出均为可解析的 JSON；验证完整 stdout，不能忽略杂音只截取 JSON | 4 | M22 在成功 stdout 的 JSON 前添加日志 |

合同未规定 JSON 键的额外字段、错误措辞、列表排序、作废类别是否保留零值键、损坏文件恢复、并发控制等，不额外要求。既有产品的精确格式只有在合同或共同基线提供保证时才能用来判错。

旧测试与新增贡献必须分别测量。先独立运行旧冒烟测试得到 baseline；再运行最终交付工作流 final。每项记录旧覆盖、新增有效断言和变异集合 K_old、K_added、K_final。报告 K_final − K_old 为净新增检出，K_old − K_final 为回退；新增测试重复检出旧测试已发现的缺陷不算新增覆盖。行为质量评价最终工作流，不因保留旧测试而扣分，但不能把旧测试的效果归功于新增技能。跨组比较同时展示质量分与净新增覆盖，不用测试数量代替贡献。

## B. 复用性：25 分

| ID | 可观察指标 | 权重 | 0 / 1 / 2 锚点 |
|---|---|---:|---|
| R01 | 可重复调用的项目测试说明：用途、运行入口、前提、如何判断成功或失败、如何保留结果 | 10 | 无可执行路径 / 可跑但需工程师猜测一个关键步骤 / 新工程师无需作者介入即可调用并解释结果 |
| R02 | 运行隔离与重复执行：独立 state、无网络和非标准库依赖、不污染原数据；连续运行两次 | 8 | 依赖作者机器或污染真实数据 / 可运行但有残留或手工重置负担 / 两次运行均独立稳定且临时状态清理或明确归档 |
| R03 | 可维护的测试入口和失败定位；旧测试仍存在且接入工作流；未来追加行为有清晰位置 | 7 | 无入口或旧测试被删除/绕过 / 入口可用但定位或扩展需明显人工追踪 / 统一或明确分步入口运行全部检查，失败能定位具体行为，扩展位置清楚 |

不要求打包、安装或特定 SKILL.md 结构；本地文档加脚本可完全满足复用要求。不因语言风格或未创建多份报告扣分。

## C. 执行可信度：15 分

| ID | 可观察指标 | 权重 | 0 / 1 / 2 锚点 |
|---|---|---:|---|
| E01 | 原运行实际执行证据：命令、工作目录/状态位置、退出结果、与交付版本的关联；成功和失败如实陈述 | 10 | 未执行，或声称执行却无任何可核对证据 / 有真实执行但版本或命令关联不完整 / 工具轨迹或原始日志能核对最终产物的运行和结论 |
| E02 | 结果可追溯与独立复跑一致性：说明区分已验证、未验证、失败和限制 | 5 | 实质性误报或证据与结论矛盾 / 结论基本准确但范围或复跑差异未说明 / 范围明确，独立复跑支持结论，差异有可检验解释 |

工程师后来运行成功不能追认作者曾运行。截图、手写 PASS 与真实工具轨迹的证据强度不同；不强制文件报告，平台提供的命令轨迹也可以。缺少执行证据导致 E01 扣分时，不再在 E02 以同一缺证扣分；E02 只评价独立的陈述准确性。

## D. 成本：单独报告

只从真实平台记录取值：完整运行的输入/输出 token、缓存 token（若有）、墙钟秒数、模型和配置、重试次数。固定起点为初始任务发送，终点为最终交付；人工等待、队列等待若可辨识则另列，不能估算扣除。单独记录评测人员耗时，不能记作模型成本。只比较同口径可观测量；缺少数据标 UNKNOWN，不按日志行数、文件数或文档长度推算 token，也不按印象评效率。若价格有事先锁定且真实的账单才报告货币成本，不临时查询价格。

## 缺陷归属与门槛

先为每个根因登记唯一 defect_id、owner、证据和受影响项。例如：错误的 summary 断言归 B08；临时目录未清理归 R02；入口漏掉旧测试归 R03；从未运行归 E01；把已知失败报告为成功归 E02。一个共享入口错误使所有检查无法运行时只归 R01/R03 中最直接的一项，其他受阻行为 UNKNOWN，不能全部判 0。一个断言错误碰巧使多个变异失败时不是多项检出。

重大缺陷独立报告，不再额外减分：

- G01 修改产品代码以完成任务（相对共同起始快照验证，测试与文档新增不算）：任务不合格。
- G02 删除旧测试或故意使旧测试不再执行：任务不合格；对应 R03。
- G03 无可执行行为测试，或交付入口因产物自身问题无法启动任何检查：不可交付；对应最直接的 R 项，其余不可验证项 UNKNOWN。
- G04 可核实的执行证据造假、已知失败宣称成功、隐藏错误使命令总是成功：不可信；归 E01 或 E02，若为测试判定错误则归对应 B 项，择唯一主因。
- G05 测试不可控地修改项目外真实用户数据：不可安全复用；归 R02。

出现任一门槛不输出可用于排名的综合分；仍报告可观察的条目分和原因，不把“未通过”误写为“总分 0”。

BLOCKED 是一次动作因外部条件不能完成；UNKNOWN 是指标目前无足够证据。环境无法启动 Python、评测平台日志丢失、变异未能可靠实现属于外部 BLOCKED/UNKNOWN，不扣作者分。交付自身缺入口、错误命令或确实未执行属于可观察缺陷，可以给 0；其连带不可观察项仍 UNKNOWN。任何 UNKNOWN 均给总分区间 [已知得分, 已知得分 + 未知项权重]，不用剔除未知项后重新归一化。区间有重叠或门槛状态不同，不给简单胜负排名。

## 固定评测操作

1. 冻结本文与 JSON，保存 SHA-256。由保管者保存组别映射；评审只得到随机运行编号、共同基线、完整匿名产物和必要执行证据。可遮盖提示中的处理组标记，但不能删改测试逻辑或关键运行上下文。先记录评审对组别的猜测与信心，承认文件内容可能暴露处理条件。
2. 取四份独立的共同基线快照，记录 Python/OS、文件校验和及旧测试内容。检查产品 diff 和旧测试保留情况。不得查看任何技能文本来解释评分要求。
3. 在各自干净临时目录按交付说明运行一次，再换新目录运行一次；无网络、无第三方包。保留命令、cwd、stdout、stderr、退出码及产物版本哈希。先不修补交付；若需要诊断性修补，原结果保留，修补结果不得冒充原交付成功。默认单次测试命令上限 60 秒，同一入口四组一致；超时先排查评测环境，不能直接将全部行为判 0。
4. 在共同产品基线上实现 M01–M22，每份只改一个指定语义。实现及参考探针在查看产物前冻结并留哈希；不能依据某组的弱点增加变异。参考探针须证明干净产品满足该行为、变异产品确实违反该行为且其他前置功能仍能达到目标路径。若基线本身违反合同，单列产品缺陷，相关项 UNKNOWN；不要求作者修改产品。
5. 对每个已验证变异，在全新副本分别执行 baseline 与 final 工作流，记录 K_old/K_final。必要时独立运行新增测试识别 K_added；若不可拆分，新增归因标 UNKNOWN，不猜测。只有干净实现通过、变异实现由相应行为断言明确失败才算 kill。语法错误、导入错误、超时、对源码哈希的检查、无关崩溃均不算有效 kill。一个变异被前置检查偶然挡住也不自动证明目标行为已覆盖。
6. 同一变异不得为各组制作不同语义版本。无效或等价变异在所有组同步标 INVALID，记录理由；它不是幸存也不是检出。固定变异无法适用时，使用静态断言检查和参考行为证据评相应条目，明确标识证据较弱；不足以区分等级则 UNKNOWN，不能悄悄补新变异。
7. 按条目完成证据表、缺陷归属和重大门槛判断，锁定每次运行的评分与理由后再解盲。复核争议只依据冻结规则，留下修订轨迹；不能在解盲后调权重。隐藏清单不提供给执行实验的 Sol，且不纳入技能输入。

## 结果表达与限制

每次运行报告：门槛状态、各项等级与证据、质量分或区间、旧覆盖/新增覆盖/回退、有效变异检出与幸存、复跑结果、实测成本。两个处理组各仅两次运行，展示全部四个原始值及组内范围；如同任务种子有配对则同时展示差值，不事后创造配对。均值只作描述，不做显著性、稳定优越或广泛因果结论；不能挑最好一次代表该组。结论最多是“在这个项目、这些配置和四次运行中观察到的差异”。产品合同仅代表 Ledger Lite，未覆盖真实服务、第三方依赖和大型项目。
