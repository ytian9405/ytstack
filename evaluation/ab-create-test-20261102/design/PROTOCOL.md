# create-test-skill 对照实验协议

实验只比较固定 Sol 模型在同一 Ledger Lite 任务上有无加载 create-test-skill 时的产物。每组两次独立运行，用于观察本任务内的重复性，不估计跨任务平均收益，也不宣称统计显著性。

两组使用相同模型、继承的相同推理设置、工具权限、原始产品文件、已有 unittest 冒烟用例和共同任务文本。每次启动不继承父会话或其他运行的历史。无技能组明确不读取现成技能；有技能组只读取冻结的 create-test-skill 及其引用资源。技能输入是实验处理的一部分，不计为生成产物。所有输入哈希及分组在 `control/assignment.json` 中保留。

两组共同任务已经明确要求项目测试技能与可执行测试，避免只向一组要求更完整的交付。评价允许不同的文件结构、篇幅、报告格式与测试数量。评分按行为和复用价值，而非按与 create-test-skill 模板是否一致。

先由 GPT-6 Astra 制定 MECE 评价框架，记录文件哈希后再启动 Sol。Astra 设计者不查看生成技能说明、旧评测或本实验产物。产物完成后，评审只得到随机编号的副本和统一客观测试记录，不提供分组映射、生成提示或处理技能输入。产物自身可能暴露处理条件，因此这是隐藏分组标签的评价，无法保证完全盲法。

目标项目为新建、无外部依赖的持久化记账 CLI，避免使用此前已生成测试的 Tiny Queue 或 ytstack 自测仓库。README 是产品合同；原有 expense_cli.py、README.md、tests/test_smoke.py 必须原样保留。正式产品代码与技能源码不得修改。

评测使用干净副本运行双方共同的 unittest 入口，并分别应用预先冻结的行为缺陷。每个缺陷单独应用，恢复后再次运行。断言失败才算检出；缺少依赖、语法错误、无法启动、无关错误或测试零发现均不算检出。记录原始测试本就能检出的缺陷，以区分新增价值。另用语义等价改写检查是否错误依赖源码文本。

正式评分采用 Astra 框架中冻结的 M01–M22，覆盖字符串保真、金额校验、ID、持久化、列表、作废及幂等、汇总、错误处理、状态初始化和 JSON 输出。保管者在框架生成前独立拟过 7 个初步缺陷；它们未进入正式评分，正式实现及验证以 `design/pre-run-freeze.json` 为准。评价规则与正式变异代码均在启动 Sol 前冻结。

只报告真实计时和可取证的资源信息。若平台未提供每个子代理的 token 用量或费用，就标记不可测，不从篇幅推算。独立运行按同一最大允许时间监管；超时或工具故障单独记录，不替换掉较差结果。

已知限制：双方仍可看到宿主共同提供的技能目录元数据；约束的是是否读取和使用技能正文。共享文件系统通过明确的目录边界隔离，未使用容器做访问控制。固定的是平台接受的模型 ID，未保证其背后的服务快照永不变化。两组都不获得隐藏评分标准、变异代码或对方产物。
